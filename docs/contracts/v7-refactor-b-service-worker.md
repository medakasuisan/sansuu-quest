## 0. なぜこの契約が必要か（背景・実装前に必ず読む）

`v7-refactor-a` で画像を `index.html` から `img/` へ外部化した結果、**オフライン動作の担保が一時的に失われている**。

```
外部化前: 全部が index.html 1ファイル → 1つキャッシュされていれば絵も揃う → 機内モードで動く
外部化後: ファイルが47個に分散       → 「47個すべて揃っている保証」がない  → 機内モードで絵が出ない可能性
```

規約 §0 は「オフライン・広告ブロッカー環境でも**ゲームは完全動作すること**」を求めている。
**本契約が完了するまで本番 push は行わない**（規約 §0 に明記済み）。本契約はその封鎖を解除するためのもの。

## 2. 実装仕様

### 2-1. `sw.js`（新規）

**キャッシュ対象（プリキャッシュ・合計47件）**

| # | 対象 | 件数 |
|---|---|---|
| 1 | `./`（＝ `index.html`） | 1 |
| 2 | `img/guide.webp` | 1 |
| 3 | `img/s01.webp` 〜 `img/s11.webp` | 11 |
| 4 | `img/K1.webp` 〜 `img/K10.webp` | 10 |
| 5 | `img/m01.webp` 〜 `img/m25.webp`（**`m13` は欠番**・作らない） | 24 |

- ファイル名は**実在するものを列挙する**。`ls img/*.webp` の実出力と一致させること（推測で書かない）
- ルートのアイコン類（`favicon.ico` / `icon-192.png` / `icon-512.png` / `apple-touch-icon.png` / `ogp.jpg`）は**プリキャッシュしない**（ゲームプレイに不要）

**キャッシュ戦略（リソース種別で必ず分ける）**

| 対象 | 戦略 | 理由 |
|---|---|---|
| `img/` 配下 | **cache-first**（キャッシュにあれば即返す。無ければ取得してキャッシュに入れる） | `vercel.json` で `immutable` 指定済み。内容が変わるときはファイル名が変わる |
| ナビゲーション要求（`request.mode === 'navigate'`）＝ `index.html` | **network-first**（まずネットワーク。失敗したらキャッシュ） | ⚠️ **本契約で最も重要**。cache-first にすると古いコードが子どもの端末に固着し、修正が永久に届かなくなる |
| **オリジンが `location.origin` と異なる要求**（gtag.js・GA4 の `/g/collect` など） | **`fetch` ハンドラで一切介入しない**（`return` して素通し） | 計測とサードパーティを壊さない |
| 上記以外の同一オリジン要求 | 素通し（介入しない） | 影響範囲を最小に保つ |

**ライフサイクル（更新事故の安全弁・この3つは必須）**

```js
const CACHE_NAME = 'sq-v1';   // ← デプロイのたびに更新する。由来をコメントで明記すること

self.addEventListener('install', e => {
  e.waitUntil(
    caches.open(CACHE_NAME)
      .then(c => c.addAll(CORE))      // CORE = index.html + guide.webp（これが失敗したら install 失敗）
      .then(() => self.skipWaiting())
  );
});

self.addEventListener('activate', e => {
  e.waitUntil(
    caches.keys()
      .then(ks => Promise.all(ks.filter(k => k !== CACHE_NAME).map(k => caches.delete(k))))
      .then(() => self.clients.claim())
  );
});
```

**プリキャッシュの二段構え（初回起動を人質に取らない）**

- **`CORE`**（`./` と `img/guide.webp` の2件）は `install` の中で**同期的に**取得する。失敗したら install を失敗させる（＝旧 SW のまま。安全側に倒す）
- **残り45件**（`img/` の 46 枚から `guide.webp` を除いた数）は `install` 完了後に**バックグラウンドで順次**取得してキャッシュに入れる。**個々の失敗を無視し、install の成否に影響させない**（電波が細い環境で初回起動をブロックしない）

### 2-2. `index.html` への登録コード

`<script>` ブロックの**末尾**（`boot` セクションの後）に追加する。

```js
/* Service Worker: オフライン動作の担保（契約 v7-refactor-b）。
 * 未対応ブラウザ・登録失敗でもゲームは通常どおり動くこと（計測と同じく no-op 方針）。 */
if ('serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('sw.js').catch(() => {});
  });
}
```

- **登録失敗でゲームを止めない**（`catch` で握りつぶす。規約 §4 の `sqTrack` と同じ思想）
- `file://` で開いた場合は `serviceWorker` が使えないが、**それでもゲームは動くこと**

### 2-3. `<head>` への preload（1行）

```html
<link rel="preload" as="image" href="img/guide.webp">
```

- **`GUIDE_IMG` の1枚のみ**。相棒画像は `partnerLineId()` がセーブを読んでから決まるため静的に書けない（正本 §5-2(c) の実測結果）
- 挿入位置は favicon 群の近く。**gtag.js の `<script>` より前に置かない**（計測の初期化順序を変えない）

### 2-4. `vercel.json` への追記

既存の `/img/(.*)` ルールは**そのまま維持**し、`sw.js` 用のルールを追加する。

```json
{ "source": "/sw.js", "headers": [ { "key": "Cache-Control", "value": "public, max-age=0, must-revalidate" } ] }
```

- **`sw.js` 自身に長期キャッシュを付けてはいけない**。SW スクリプトが古いままキャッシュされると、更新が永久に届かなくなる

### 2-5. 迷ったら止まる

仕様に書かれていない判断（プリキャッシュ対象の実ファイル数が契約の記載と合わない、`sw.js` の scope がルートにならない、既存の `vercel.json` の書式と衝突する等）に遭遇したら、**推測で進めず `### 要判断` として停止し、実測値を添えて報告**すること。

## 4. セーブに触る場合の必須ブロック

**該当なし。** 本契約はセーブデータに一切触らない。

- 追加・変更する `game` のキー: **なし**
- `SAVE_KEY`（`sq_save_v2`）: **変更なし**
- `selfTestSave()` へのケース追加: **なし**（ただし D9 で**回帰確認として実行**する）
- 根拠: 変更対象は SW・登録コード・preload タグ・配信ヘッダのみ。`localStorage` の読み書き経路に一切触れない。
- 万一の切り戻し: `git revert` で復旧できるが、⚠️ **SW は revert してもブラウザに残る**。切り戻す場合は `self.registration.unregister()` を仕込んだ「墓石 SW」を配るか、`CACHE_NAME` を変えて全キャッシュを破棄する必要がある。**この点が本契約のロールバック上の唯一の注意点**であり、D5 / D6 を最重要 DoD にしている理由
