## 2. 実装仕様

### 2-1. 画像の抽出とファイル名

`index.html` 内の `data:image/webp;base64,...` を持つ定数は次の 3 つ。**キーとファイル名の対応を厳密に守る**こと。

| 定数 | キー | 出力ファイル名 | 枚数 |
|---|---|---|---|
| `GUIDE_IMG`（単独の定数） | — | `img/guide.webp` | 1 |
| `SCENE_IMG` | `s01`–`s11` | `img/s01.webp` … `img/s11.webp` | 11 |
| `SCENE_IMG` | `K1`–`K10` | `img/K1.webp` … `img/K10.webp` | 10 |
| `MONSTER_PNG` | `1`–`25`（**13は欠番**） | `img/m01.webp` … `img/m25.webp`（**2桁ゼロ埋め**・`m13.webp` は作らない） | 24 |

合計 **46枚**。

- 抽出は使い捨てスクリプト（python3 等）で行ってよい。**スクリプトを repo に残さない**
- **キー名を勝手に正規化しない**（`K1` を `K01` にしない・`s01` を `s1` にしない）。既存の `SCENE_IMG[def.scene]` は `STORY` 定義の `scene: 'K1'` 等をそのまま添字にしているため、**キーを変えると物語の背景が出なくなる**

### 2-2. 定数の置き換え

値だけを URL 文字列に差し替える。**変数名・オブジェクトの形・キーは変えない。**

```js
// before
const GUIDE_IMG = 'data:image/webp;base64,UklGRgZpAABX...';
const SCENE_IMG = { s01: 'data:image/webp;base64,...', ..., K1: '...', ... };
const MONSTER_PNG   = { 1: 'data:image/webp;base64,...', ..., 25: '...' };

// after
const GUIDE_IMG = 'img/guide.webp';
const SCENE_IMG = { s01: 'img/s01.webp', ..., K1: 'img/K1.webp', ... };
const MONSTER_PNG   = { 1: 'img/m01.webp', ..., 25: 'img/m25.webp' };
```

- パスは**相対パス**（`img/...`）にする。先頭スラッシュ（`/img/...`）にしない
- 定数の直前にあるコメント（差し替え口の説明）は、**内容が実態と合わなくなるなら同じターンで書き換える**（規約 §7 の同期規律）

### 2-3. `vercel.json`（新規）

```json
{
  "headers": [
    {
      "source": "/img/(.*)",
      "headers": [
        { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }
      ]
    }
  ]
}
```

- `index.html` のヘッダは**現状のまま**（`public, max-age=0, must-revalidate`）。上書きしない
- `immutable` を付ける前提として、**画像を差し替えるときは新しいファイル名にする**運用になる。この点を `vercel.json` にコメントで書けないため、**`docs/refactor-plan-2026-07-27.md` を参照する旨を実装報告に明記**すること（規約 §5 の手順改訂は秘書が行う）

### 2-4. `.vercelignore`

現状:
```
docs
assets
.claude
CLAUDE.md
```
`img/` は**除外しない**（配信される必要がある）。冒頭のコメントが「画像は base64 埋め込み済みなので assets/ を配信する必要はない」という**実態と合わない説明になる**ので、実態に合わせて書き換えること。

### 2-5. 迷ったら止まる

仕様に書かれていない判断（例: 抽出した画像の枚数が46枚にならない、キーの対応が表と食い違う、`data:image` が定数以外の場所からも見つかる）に遭遇したら、**推測で進めず `### 要判断` として停止し、実測値を添えて報告**すること。

## 4. セーブに触る場合の必須ブロック

**該当なし。** 本契約はセーブデータに一切触らない。

- 追加・変更する `game` のキー: **なし**
- `SAVE_KEY`（`sq_save_v2`）: **変更なし**
- `selfTestSave()` へのケース追加: **なし**（ただし D7 で**回帰確認として実行**する）
- 根拠: 変更対象は画像定数の値と配信設定のみ。`localStorage` の読み書き経路に一切触れないため、規約 §2-2 R1〜R5 のいずれにも抵触しない。
- 万一の切り戻し: `git revert` 1発で完全復旧でき、**子どもの進捗は revert しても無傷**（セーブ形式が不変のため）
