## 2. 実装仕様

### 2-1. 数の生成（正しさの核）

```
makeMultiplication({ digits, allowZero })
  digits='easy10' : a = 何十(20,30,…,90),      b = rand(2,9)
  digits='2x1'    : a = rand(11,99),           b = rand(2,9)
  digits='3x1'    : a = rand(101,999),         b = rand(2,9)
  digits='2x2'    : a = rand(11,99),           b = rand(11,99)
  allowZero=true  : 1/10 の確率で a または b を 0 にする（K4）
  返り値 { a, b, p, parts }
    p     = a*b
    parts = 被乗数を位で分解した { a1, a2 }（例 23 → {a1:20, a2:3}）
            2x2 のときは乗数側も { b1, b2 }（例 45 → {b1:40, b2:5}）を持つ
```

`assertMultiplication(d)` が満たすべき不変条件:

| # | 条件 |
|---|---|
| A1 | `a` `b` `p` がすべて 0 以上の整数 |
| A2 | `p === a * b`（**独立に再計算**して一致） |
| A3 | `digits` ごとの桁範囲に収まる（`allowZero` で 0 になった場合を除く） |
| A4 | `parts.a1 + parts.a2 === a`（`b1`/`b2` がある場合は `b1 + b2 === b`） |
| A5 | `parts.a1` は 10 の倍数（位で分けているため） |
| A6 | `a` または `b` が 0 のとき `p === 0` |

### 2-2. 解説ステップ `bunpaiSteps(d)`

分配法則で「考え方を追体験」させる。**答えを先に言わない**。

23×4 のとき、steps は次の内容を**この順で**含む:
1. 「23 を **20 と 3** に分けるよ」
2. 「20×4＝**80**」
3. 「3×4＝**12**」
4. 「80＋12＝**92**」

- 0 の問題（`mulZero`）は分配せず、「**どんな数に 0 をかけても 0**」「0 に どんな数をかけても 0」を説明する
- `2x2` は乗数も分解する（45×23 → 45×20 と 45×3）
- 文言はひらがな主体・既存 `kukuSteps()` の書き味（`**強調**` 記法）に合わせる

### 2-3. たしかめ算（`checkFormula` 相当）

かけ算は**交換法則で確かめる**: `${b} × ${a} ＝ ${p}`（順番を入れ替えても同じ）。
K3（交換法則）を毎問さりげなく教えることになり、憲法「乗法の順序非依存」とも整合する。

### 2-4. 生成器 9 本

共通スキーマ `{prompt, fields, answer, explain, d}` を**厳守**（既存わり算生成器と同一）。

| 生成器 | 内容 | digits | 指導要領 |
|---|---|---|---|
| `mulTens` | 何十×1位数（20×3）。「10 のたばが 2×3 こ」で説明 | easy10 | K1 導入 |
| `mulCalc2x1` | 2位数×1位数 | 2x1 | K1 / T1 |
| `mulCalc3x1` | 3位数×1位数 | 3x1 | K1 |
| `mulCalc2x2` | 2位数×2位数 | 2x2 | K1 / T1 |
| `mulZero` | 的当て文脈の 0 のかけ算（0×3 / 3×0） | 2x1 + allowZero | K4 |
| `mulLaw` | 計算のきまりの穴埋め（例: 4×7×25 を工夫して計算・交換/結合を具体数で） | — | K3 |
| `mulEstimate` | 見積り 2択（19×6 は 120 より 大きい / 小さい） | 2x1 | K5 |
| `wordTimes` | 文章題・倍（1本 85円のリボンを 25本） | 2x2 or 2x1 | K2 |
| `wordInverse` | 文章題・除法の逆（4等分した1つ分が 9cm。はじめは？） | 2x1 | K2 |

- 文章題の素材は既存 `ITEMS` / `CONTAINERS` を再利用する（新規に増やさない）
- `mulEstimate` の選択肢は `fields` の既存仕組みで表現できる形にする。**UI エンジンを改造しないと出せない形にはしない**（2択が既存の数値入力で表現できなければ「見積りの答えの十の位を答える」等、既存 UI で成立する形に落とす。判断に迷ったら `### 要判断` で停止すること）

### 2-5. visual（アレイ図）の扱い ⚠️

`renderVisual(v)` は `groups × groupSize + rest` 個の emoji を実際に DOM へ並べる。
**3位数×1位数（最大 999×9＝8,991）で visual を付けると DOM が爆発してフリーズする。**

- **積 `p` が 60 以下のときだけ** visual を付ける（`{ groups: b, groupSize: a, rest: 0, groupTag: '1つぶん', … }`）
- `p > 60` のときは **`visual` を省略する**（`renderVisual` は falsy を渡すと空を返す実装なので安全）
- visual を付けた場合の不変条件: `groups × groupSize + rest === p`

### 2-6. CURRICULUM（4 単元）

既存のプレースホルダ `{ id:'mul', …, enabled:false }` を**次の 4 単元に置き換える**（`div-*` 3 単元と `hissan` は触らない）。

| id | title | 出題プール |
|---|---|---|
| `mul-basic` | かけざんの きほん | `mulTens` / `mulCalc2x1` を中心 |
| `mul-big` | 大きな かけざん | `mulCalc3x1` / `mulCalc2x2` を中心 |
| `mul-tech` | かけざんの わざ | `mulLaw` / `mulEstimate` / `mulZero` |
| `mul-word` | かけざんの ぶんしょうだい | `wordTimes` / `wordInverse` |

- `emoji` / `desc` はひらがな主体で実装係が起案してよい（`### 要判断` 不要）
- `questions: 10`・`enabled: true`・重み付き `pool` の書式は既存 `div-*` に合わせる

## 4-2. 追補 A（2026-07-25・実装後に判明したブロッカーへの対応）— 状態: **LOCKED（佐々木さん承認）**

### 経緯
実装係が実機打鍵して判明: 既存 `padInput()` が**答えを 2 桁までしか受け付けない**。
わり算は答えが常に 1 桁（商 1〜9 / あまり 0〜8）のため誰も踏まなかったが、かけ算は積が 3〜4 桁になる。
実測: `mul-big` **0/10**（構造的に確定）/ `mul-basic` 1/10 / `mul-tech` 3/10 / `mul-word` 0/10。

### 追補の内容（§1「やらないこと」の UI エンジン不可侵を、以下の範囲に限って解除する）

**A-1. 入力桁数の上限を 2 桁 → 4 桁に拡張**
- 対象: `padInput()` の `if (cur.length >= 2) return;` の定数のみ
- わり算への影響なし（答えが常に 1 桁のため、上限が 2 でも 4 でも正解入力の経路は不変）
- `padDelete()` / `syncAnswerBoxes()` / フィールド移動ロジックは**変更しない**

**A-2. 解答欄が 4 桁を収容できるようにする**
- 対象: `.ans-box` の幅・フォントサイズ（既存 3 ブレークポイント: 96px / 82px / **320px 時 74px**）
- 桁数に応じてフォントを縮める等、**既存の見た目を大きく変えない**方法を採る
- わり算プレイ時（1 桁表示）の見た目を変えないこと

**A-3. ホームのセクション見出しを中立化**
- 対象: `index.html` の `<div class="unit-label">🌲 わりざんのもり</div>` の文言のみ
- **`🌲 ぼうけんの もり`** に変更する（佐々木さん選択・2026-07-25）
- ロゴ `÷さんすうクエスト` とタグライン `わけて わかる、わり算のぼうけん！` は**触らない**（ブランディングは Phase 4 の担当）
