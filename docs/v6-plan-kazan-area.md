## 1. 章立ての方法（v5 で確立したテンプレートの一般化）

新エリアの物語は毎回この型で作る（v5「かずのもり」14話で実証済み）:

1. **話数はマイルストーン駆動**（時間駆動にしない）。加入・累計正解数・初✗後の正解・進化・コンプの各ゲーム イベントに1話を紐づける
2. **構成テンプレ**: 序（世界の異変=課題提示）→ ライン加入章×3 → 「まちがいの肯定」章（罰ゼロの物語化・必ず1話入れる）→ 進化章 → レア/コンプ章 → 終（**次エリアへのクリフハンガー**）
3. **1話 ≒ 3画面**（v5.2 確定仕様）・各章に小さな「事件」・モンスター発話あり・ひらがな多め
4. **ペーシングは逆算**: 「約1週間で全話」(1日15分 ≒ 正解10問) から各 trigger 値を決める（v5.2 の裁定を踏襲）
5. **台本は bible が正本**。実装での要約・言い換えは禁止（一字一句照合で検収）

### v6 の章立て案（14話・トリガーは v5.2 実測ペースを流用）

- 序「かざんに ついた」（初回かざん入場 / 新シーン K1）
- 1-1〜1-3: ライン1加入 → 累計10問 → 事件
- 2-1〜2-3: ライン2加入 → まちがいの肯定章（かざん版）→ 初進化
- 3-1〜3-3: ライン3加入 → 累計50問 → 3ライン最終進化
- 4-1〜4-3: レア/図鑑23体 → 24体コンプ → おまつり（かざん版）
- 終: 次エリア（どうくつ=筆算）への手紙
- 物語の芯（**2026-07-18 Phase 0 確定・佐々木さん裁定=案B**）: 「**きえた ひだねを さがして**」— かざんの火が消えてみんな困っている。**どんなに かけても 0 は 0**（火種がゼロだと何をかけても増えない）という「0の謎」を序盤の事件にし、終盤で「さいしょの ひとつぶの ひだね(1)」を見つけると倍々に燃え広がって火山が復活する。0の乗法(K4)が物語の芯そのものになり、「小さな一歩があれば かけ算で大きくできる」というメッセージを担う

## 2. 問題の作成方法（わり算で確立した方式の踏襲）

**原則: 構成的生成 + 不変条件アサート + 起動時 selfTest 200問**。答えから逆算して問題を組み立てるので、範囲外・矛盾は原理的に発生しない。

### 2-1. 数の生成（正しさの核）

```
makeMultiplication({ digits, allowZero })
  digits='2x1': a=rand(11,99)※何十を含む, b=rand(2,9)   … K1前半
  digits='3x1': a=rand(101,999), b=rand(2,9)             … K1
  digits='2x2': a=rand(11,99),  b=rand(11,99)            … K1後半
  digits='easy10': a=何十(20..90), b=rand(2,9)           … 導入(20×3=10が2×3こ)
  allowZero: 1割の確率で a または b を 0 に(K4)
  返り値 { a, b, p:a*b, parts:分配分解 {a1,a2} or {b1,b2} }
assertMultiplication(d): p === a*b を独立再計算で検証・桁範囲検証・parts の和が元の数に一致
```

### 2-2. 生成器ロスター（共通スキーマ {prompt, fields, answer, explain, d} を厳守）

| 生成器 | 内容 | 指導要領 |
|--------|------|---------|
| `mulTens` | 何十×1位（20×3）。10のたばで考える解説 | K1導入 |
| `mulCalc2x1` | 2位数×1位数。解説は分配法則ステップ固定型 | K1/T1 |
| `mulCalc3x1` | 3位数×1位数 | K1 |
| `mulCalc2x2` | 2位数×2位数。乗数を 40+5 に分ける解説 | K1/T1 |
| `mulZero` | 的当てゲーム文脈の 0 のかけ算（0×3, 3×0） | K4 |
| `mulLaw` | 計算のきまり穴埋め（4×7×25 の工夫・交換/結合/分配を具体数で） | K3 |
| `mulEstimate` | 見積り（19×6 は 20×6=120 より小さい、どっち?の2択） | K5 |
| `wordTimes` | 文章題・倍（「1mが85円のリボンを25m」型・ねだん×長さ） | K2 |
| `wordInverse` | 文章題・除法の逆（「4等分した1つ分が9cm。はじめは?」） | K2 |

- 解説ステップは `bunpaiSteps(d)`（分配法則ベース）を全生成器で共通化 — わり算の `kukuSteps` に相当。例: 「23を **20と3** に分けるよ → 20×4=**80** → 3×4=**12** → 80+12=**92**」
- visual は既存の emoji グループ図を流用（アレイ配置: groups=b, groupSize=a1 など。10のたば表現は新規 visual タイプ `bundle` を追加検討 — Phase 2 で実装係に設計させ、jsdom で図と数の一致を検証）
- `checkFormula` は逆算確かめ（92÷4=23 …除法との相互関係、指導要領イ(ｱ)）

### 2-3. selfTest 拡張（不変条件）

- p = a×b の独立再計算一致 / 桁範囲 / parts 分解の和一致 / 0問題は答え0 / 見積り問題は丸め方向の整合 / visual 個数 = 積
- 既存6ケースに9生成器×200問を追加。**既存わり算ロジックは不可侵**（v4以来の鉄則）

## 5. 教育設計上の合意事項（全 Phase 共通の基本原則）

- **乗法の順序非依存（2026-07-18 佐々木さん裁定）**: 乗法は可換（a×b=b×a）であり、数学的に正しいものを採用する。教科書・学校テストが「1つ分×いくつ分」の順序を強制する場合があるが、本アプリでは**式の順序を採点基準にしない**。具体的には——
  - 式を答えさせる問題を出す場合は両順序を正解にする（採点ロジックで機械保証・selfTest に両順序受理のケースを含める）
  - 解説では「じゅんばんを かえても こたえは おなじだよ（4×25 でも 25×4 でも 100）」を積極的に教える（交換法則 K3 の正式内容であり指導要領と矛盾しない）
  - アレイ図 visual は「どちらから数えても同じ」の直観を与える配置にする
  - 「おうちのひと」画面に方針注記を1枚入れる: 学校のテストでは式の順序を指定される場合がある旨と、本アプリが数学的正しさを優先する旨（子どもが混乱したときの保護者向け説明）
- ○✗は正直・✗の帰結は「進まないだけ」の罰ゼロ。✗でも「かんがえたひかり」演出は かざんでも継承
- 解説は「答えを教える」でなく「考え方の追体験」（分配法則ステップ）。解説を読む行動に報酬（レア出現条件）
- 数学的な正しさは selfTest が機械保証。日本語の自然さ・発達段階適合は佐々木さんの目視が最終ゲート
- 答えの吟味（見積り・逆算確かめ）を問題タイプとして組み込む — 指導要領が最重視する「結果を振り返る態度」の実装
