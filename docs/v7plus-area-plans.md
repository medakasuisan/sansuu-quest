## 1. v7「ひっさんのどうくつ」— 加法・減法の筆算 A(2)

**指導要領の要求**: 3位数・4位数の加減が2位数の基本計算の合成でできる理解／筆算の仕方／確実な習得／暗算(2位数どうし)／見積り(389+4897→約400+約5000=約5400)／計算の工夫(387+75+25)と確かめ。

### 数の生成（構成的・繰り上がり制御が核）

```
makeAddSub({ digits, carries })
  digits: 3 or 4 / carries: 繰り上がり(下がり)の回数を指定して各位の数字を逆算構成
  加法: 指定位の (digit_a + digit_b) ≥ 10 になるよう構成 / 減法: 借りが発生するよう構成
assertAddSub: 和・差の独立再計算一致／各位の繰り上がり実発生数 = carries 指定値／桁範囲
```

### 生成器ロスター

| 生成器 | 内容 |
|--------|------|
| `addVert3` / `addVert4` | 3位数・4位数の加法筆算（U3グリッド解答・繰り上がり数はレベル連動） |
| `subVert3` / `subVert4` | 減法筆算（連続繰り下がり: 1000-278 型を含む） |
| `mentalAddSub2` | 2位数どうしの暗算（通常入力・制限なし=急がせない） |
| `estimateAddSub` | 見積り（「答えは約何千?」choice型・位を揃えないミス発見の文脈） |
| `checkAnswer` | 確かめ問題（たし算の答えをひき算で確かめる式を選ぶ） |
| `kufuuAdd` | 計算の工夫（387+75+25 → 足して100を先に・choice型） |
| `wordAddSub` | 文章題（合わせて・違いは・3位数の買い物文脈） |

- 解説ステップ: 位ごと分解型 `kuraiSteps(d)`（一のくらいから順に・繰り上がりの1を明示）。visual は①①/⑩⑩/💯 の束図（PDFの図と同型・既存emoji図を拡張）
- **世界観**: 洞窟の地層＝位取り（一のくらいの層→十のくらいの層→…）。繰り上がり＝「10こ集まると上の層に登れる」。物語の芯（案）:「**10のちからで ふかい どうくつを のぼる**」
- **モンスター方向**: くりあがり系（積み上がると上へ登る岩虫）／くりさがり系（となりから借りるコウモリ）／位取り系（層の番人ゴーレム）＋レア3（暗算・見積り・工夫）
- **主コスト**: U3 筆算グリッド。実装係へは「マス目DOM・フォーカス自動移動・繰り上がりメモは任意入力(採点対象外)」まで指定して発注

## 2. v8候補「とけいのとう」— 時刻と時間 C(2)

**指導要領の要求**: 秒の理解(1分=60秒)／日常生活に必要な時刻と時間を求める(正時・正午またぎを含む)／複雑な単位換算はいたずらに扱わない（←出題範囲の上限として遵守）。

### 生成器ロスター

| 生成器 | 内容 |
|--------|------|
| `timeAfter` | 「10時40分の 50分あとは?」（正時またぎを重み高で構成） |
| `timeBefore` | 「じゅぎょうが 11時30分におわる。45分まえは?」 |
| `timeDiff` | 2時刻の間の時間（アナログ時計2つ＋数直線visual・PDFの図と同型） |
| `secUnits` | 1分=60秒の簡単な換算（90秒=1分30秒）＋「10びょうで できることは?」choice型の量感問題 |
| `wordTime` | 文章題（家を出る時刻の逆算・日常文脈のみ） |

- 内部表現は**すべて分（秒問題のみ秒）の整数**で持ち、時:分への表示変換を関数1本に集約。assert: 逆変換一致・またぎ境界
- visual: U2 の初出。アナログ時計SVG（針の角度=時刻の機械検証）＋時間の数直線
- **世界観**: 時計塔。物語の芯（案）:「**とまった とけいの はりを うごかせ**」。秒の量感ミッション（「60びょうで なんかい ジャンプできる?」→おうちのひとと実測）を日替わりミッションに接続
- **モンスター方向**: 長針・短針・秒針の3兄弟／ふりこ系／レア=時間の妖精

## 3. v9候補「ほしぞらのてんぼうだい」— 大きな数 A(1)

**指導要領の要求**: 万の単位(1億まで)／10倍・100倍・1000倍・1/10／相対的な大きさ(500は百が5こ)／等号・不等号・数直線。

### 生成器ロスター

| 生成器 | 内容 |
|--------|------|
| `bigRead` | 漢字表記↔数字の変換（「三千五百二十万」→35200000・可逆生成で機械検証） |
| `bigTimes` | 10倍/100倍/1000倍/1/10（234→2340・位のずれを束図で解説） |
| `bigRelative` | 相対的な大きさ（「3800は 100が なんこ?」「10000kgはゾウ約10とう分」文脈） |
| `bigCompare` | 大小比較（不等号 choice・大きい位から比べる解説） |
| `bigLine` | 数直線の目盛り読み（1目盛り=1万/10万のスケール切替） |

- assert: 変換往復一致・目盛り値=位置×刻み。**新規UI不要（U1/U2の再利用のみ）＝最軽量エリア**。実装コストを下げたい回に挟むのに最適
- **世界観**: 展望台から星を数える。「10ばいの まどガラス」をのぞくと星が10倍に。1億=いちばん遠くの銀河
- **モンスター方向**: 位の星座系（万・十万・百万…で進化）／レア=一億星の主

## 4. v10候補「しずくのうみ」— 小数 A(5)

**指導要領の要求**: 端数部分の表現(2L5dL=2.5L)／1/10の位・小数点／小数の加減(1/10の位まで)／数直線での位置づけ・0.1と1/10の関連（→分数エリアと相互リンク）。

### 数の生成（**実装上の最重要罠: 浮動小数点を使わない**）

```
内部表現は「0.1 が何こ」の整数(tenths)で統一。2.5 → 25 として生成・演算・採点し、表示時のみ小数化。
assert: tenths 整数演算の一致（0.1+0.2 問題を float で作ると 0.30000000000000004 事故になる）
```

### 生成器ロスター

| 生成器 | 内容 |
|--------|------|
| `decMeaning` | 量の表現（「2Lと5dLで □.□L」・水のかさ文脈） |
| `decCompare` | 大小比較（2.4 と 3.1・数直線visualつき） |
| `decAddSub` | 小数の加減（0.1が何こ、で整数に直す解説を固定型に） |
| `decLine` | 数直線の目盛り読み（0〜3を0.1刻み・PDFの図と同型） |
| `decUnits` | 「1.5は 0.1が なんこ?」（相対的な大きさ） |

- 表示ルール: 答えの表記は「1」（1.0 でも正解扱い・指導要領の「1, 1.0, 10/10」多様表記の記述に準拠）
- **世界観**: 1のしずくが10この小さなしずくに分かれる海。0.1=こしずく
- **モンスター方向**: しずく分裂系／小数点のヤドカリ（点の位置で大きさが変わる）／レア=10/10=1 の真珠

## 5. v11候補「おかしのくに」— 分数 A(6)

**指導要領の要求**: 等分してできる部分の大きさの表現／分母・分子／単位分数の幾つ分（2/3は1/3の2こ分・4/3など1超も知る）／同分母の加減(真分数どうし・和が1まで＋その逆の減法)／0.1=1/10 の数直線関連付け。

### 数の生成

```
makeFraction({ type })  分母 den=2..10、分子 num を type 別に構成
  加法: num1+num2 ≤ den（和が1まで・指導要領の範囲上限を機械保証）
  減法: その逆(真分数どうし)
assert: 範囲制約・テープ図の塗り数=分子・約分は登場させない(3年生範囲外)
```

### 生成器ロスター

| 生成器 | 内容 |
|--------|------|
| `fracMeaning` | テープ図→分数（「色のついたところは 何分の何?」） |
| `fracUnit` | 単位分数の幾つ分（「2/3は 1/3の なんこ分?」・4/3型も低頻度で） |
| `fracCompare` | 同分母の大小（テープ図visual併記） |
| `fracAddSub` | 同分母の加減（「1/5mと2/5mを合わせると」量分数文脈・和≤1） |
| `fracDecLink` | 0.3=3/10 の関連付け（上下2段数直線visual・PDFの図と同型） |

- 新規入力: 分子/分母の2欄入力（既存fields拡張・U1〜U3不要）。テープ図はU2で描画
- **世界観**: ケーキ・チョコを等分するお菓子の国。「はんぶんこ」の発展形として導入
- **モンスター方向**: 等分ケーキ精霊（形態で2等分→4等分→8等分）／分母分子の2人組／レア=1をこえる分数(4/3)の大食い王

## 6. v12候補「はかりのいちば」— 長さ・重さ C(1)

**指導要領の要求**: km・g・kg・t／適切な単位と計器の選択／およその見当／単位の関係の統合的考察(k=1000倍・m=1/1000 の接頭語)／正味の重さ=全体−容器。

### 生成器ロスター

| 生成器 | 内容 |
|--------|------|
| `unitConvert` | 換算（3km500m=□m・1kg=1000gの範囲のみ・複雑換算はいたずらに扱わない） |
| `unitChoice` | 単位の選択（「プールのたての長さに合うのは? mm/cm/m/km」choice型） |
| `toolChoice` | 計器の選択（「木のまわりの長さをはかるなら? ものさし/まきじゃく/はかり」choice型） |
| `netWeight` | 正味の重さ（「箱ごと1kg200g、箱は200g。中身は?」） |
| `unitPrefix` | 接頭語の関係（「kが つくと 何倍?」・km/kg を並べて統合的に） |

- assert: 換算の往復一致。choice の誤答選択肢は「隣の単位」から機械構成（でたらめ選択肢を作らない）
- **実測体験との接続**: 「1kgをもってみよう」「学校まで歩いて何分?」は日替わりミッション＋おうちのひと画面に「実物でやってみよう」カードを出す（アプリで完結させない設計・指導要領の実感重視に準拠）
- **世界観**: 市場で買い物（はかり・りょうてんびん）。モンスター方向: てんびん系／おもり系／レア=1トンの巨人

## 7. 編入ユニット「□を用いた式」A(7) — 単独エリアにしない

**指導要領の要求**: 未知数を□で表して立式／□に当てはまる数を調べる(順に当てはめ・逆算)／式と図の関連付け。

- 分量が小さく、内容的に**全エリアの「まとめ・接続」の性格**を持つ（加減乗除の相互関係を使う）ため、単独エリアではなく**既存エリアへの後付けスキル**として編入する:
  - かずのもり に `boxDiv`（□÷3=4、12÷□=3）
  - かざん に `boxMul`（□×3=12 ←わり算で逆算・乗除の相互関係）
  - どうくつ に `boxAddSub`（□+8=17 ←ひき算で逆算・逆思考文章題）
- 生成器は「答えから式を構成」する既存方式そのまま。assert: 逆算解の再代入一致
- 各エリアの図鑑に「はてなの精」系モンスター1体ずつを追加配置（□のマスク姿→正解すると素顔がチラ見え、の演出案）
- 発注は各エリアのマイナーアップデート（v7.1 等）として1回ずつ・小粒 Phase 2+4 のみ

## 8. v13候補「グラフのはかせラボ」— 表と棒グラフ D(1)

**指導要領の要求**: 観点による分類整理と表／棒グラフの読み書き(最小目盛り1・10・100中心、2・5・20・50にも触れる)／二次元の表／複数グラフの組み合わせ・比較から見いだしたことの表現。

### 生成器ロスター

| 生成器 | 内容 |
|--------|------|
| `graphRead` | 棒グラフの値読み（「いちばん多いのは?」「ハンカチおとしは何人?」） |
| `scaleRead` | 目盛りの読み（1目盛り=2/5/20 のグラフ・「1目盛りいくつ?」を先に問う2段構成） |
| `tableSum` | 二次元表の合計欄（1組2組の遊び調べ・PDFの表と同型のデータを乱数構成） |
| `graphCompare` | 2つのグラフの比較（「1組で2組より多い遊びは?」choice型） |
| `dataSort` | 分類整理（ばらばらの記録→正しい表を選ぶ choice型） |

- データ生成: カテゴリ度数分布を乱数構成→U2でSVG棒グラフ描画。assert: 描画バーの高さ=データ値・合計欄=行列の和
- **世界観**: 研究所でもりの生き物調査（これまでのエリアのモンスター出現数を集計する自己言及ネタも可）
- **モンスター方向**: 棒グラフ姿のトーテム系／集計妖精／レア=二次元表の司書

## 9. 部分実装「かたちのしま」— 図形 B(1)（優先度低・最後）

**アプリで扱う範囲**: 二等辺三角形・正三角形の弁別（辺の長さ表示→なかま分け choice）／角の大小比較／円の半径・中心・直径（直径=半径×2）／球の切り口（choice）。
**アプリで扱わない範囲**: コンパス・定規の作図、紙折り、模様づくり → 「おうちのひと」画面に実物活動カードを出す（指導要領が具体的活動を重視するため・アプリで代替しない）。

- 生成器: `triClassify` / `circleParts`（半径3cmの円の直径は?）/ `angleCompare`（U2でSVG描画・辺長ラベルつき三角形）
- assert: 分類定義との一致（2辺相等=二等辺・3辺相等=正三角形）・直径=2×半径
- 単独エリアとして成立はするが体験の核（作図）を外に出すため**優先度は最後**。エリア名・世界観は着手時に壁打ち

## 10. 推奨実装順序と理由（佐々木さん裁定用）

| 順 | エリア | 主な理由 |
|----|--------|---------|
| v6 | かざん(乗法) | ストーリー予告済み・計画済み |
| v7 | どうくつ(筆算) | ストーリー予約済み・かけ算の筆算(v6の先)にもU3が効く |
| v8 | とけいのとう(時刻) | 日常効用が最大・U2(SVG)の初出として最適 |
| v9 | ほしぞら(大きな数) | 新規UIゼロで最軽量・息抜き回 |
| v10 | しずくのうみ(小数) | U2再利用・分数の前提 |
| v11 | おかしのくに(分数) | 小数とセットで数直線関連付け(指導要領の取扱い(5)) |
| 随時 | □の式(編入) | v7完了後、各エリアに小粒追加 |
| v12 | はかりのいちば(長さ重さ) | choice中心・ミッション連携の実験台 |
| v13 | グラフのはかせラボ | SVGグラフ描画は熟れてから |
| 最後 | かたちのしま(図形・部分) | 体験の核が実物のため |

> 学校の進度と息子くんの「今習っているところ」に合わせて順序は随時入れ替えてOK（各エリアは疎結合・依存は U1〜U3 部品の初出順のみ）。

- 1エリアの想定規模は v6 と同等（bible 約110行・生成器5〜9本・画像 12+10枚・Sonnet 委譲4〜5回）
